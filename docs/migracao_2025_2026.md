# Migração para IRPF 2026 com XML 2026 + referência 2025

Este fluxo é diferente de `clone`.

- `clone` serve para trocar/sanitizar identidade, CPF, endereço e recibos.
- `migrar` serve para atualizar uma declaração **IRPF 2026 que já abre no programa da Receita**, usando planilhas atuais e, opcionalmente, o XML entregue em 2025 apenas como referência.

## Por que mudou

Não é seguro usar o XML 2025 diretamente como base do IRPF 2026. Na prática, o programa 2026 espera uma estrutura interna diferente.

Exemplo observado nos XMLs:

```text
2025: classeJava="serpro.ppgd.irpf.DeclaracaoIRPF"
2026: classeJava="serpro.ppgd.irpf.negocio.DeclaracaoIRPF"
```

Também muda o prefixo dos `tipoItens`:

```text
2025: serpro.ppgd.irpf.bens.Bem
2026: serpro.ppgd.irpf.negocio.bens.Bem
```

Por isso, o fluxo correto é:

```text
XML 2026 reconhecido pelo programa da Receita
+ planilha atualizada
+ XML 2025 como referência opcional
= XML 2026 atualizado e validável no IRPF 2026
```

## O que o comando faz

O comando `irpf-importer migrar`:

1. Lê o XML base 2026, criado/importado pelo programa oficial IRPF 2026.
2. Preserva a estrutura `serpro.ppgd.irpf.negocio.*` do IRPF 2026.
3. Usa o XML 2025 somente para relatório/comparação, quando informado.
4. Preserva recibos e metadados de transmissão por padrão.
5. Só limpa recibos se `--limpar-recibos` for informado explicitamente.
6. Opcionalmente troca CPF/nome se `--target-cpf` e `--target-name` forem informados.
7. Aplica a planilha de Bens com `upsert` seguro.
8. Aplica a planilha de Proventos, quando informada.
9. Recalcula o `.conf`, exceto quando usado `--sem-recalcular-conf`.
10. Pode gerar relatório JSON com `--report`.

## Comando recomendado em dry-run

Use primeiro sem gravar resultado final:

```bat
irpf-importer migrar ^
  --base-xml-2026 "data\work\declaracoes\SEU_CPF\SEU_CPF-0000000000.xml" ^
  --referencia-xml-2025 "data\input\xml_2025\SEU_CPF-1839317427.xml" ^
  --target-dir "data\work\migracao_2026" ^
  --bens "data\input\bens\bens_2025_preparado_importacao.xlsx" ^
  --proventos "data\input\proventos\proventos_2025_preparado_importacao.xlsx" ^
  --dry-run ^
  --sem-recalcular-conf
```

O `dry-run` monta tudo em pasta temporária, calcula os impactos e não grava a declaração final.

## Execução real em pasta de trabalho

Depois de validar o `dry-run`:

```bat
irpf-importer migrar ^
  --base-xml-2026 "data\work\declaracoes\SEU_CPF\SEU_CPF-0000000000.xml" ^
  --referencia-xml-2025 "data\input\xml_2025\SEU_CPF-1839317427.xml" ^
  --target-dir "data\work\migracao_2026" ^
  --bens "data\input\bens\bens_2025_preparado_importacao.xlsx" ^
  --proventos "data\input\proventos\proventos_2025_preparado_importacao.xlsx" ^
  --irpf-dir "%IRPF_DIR%" ^
  --report "data\reports\migracao_2025_2026.json"
```

O arquivo final será gerado em uma pasta por CPF:

```text
data/work/migracao_2026/<CPF>/<CPF>-0000000000.xml
```

## Compatibilidade

O argumento antigo `--source-xml` ainda existe como alias de compatibilidade, mas agora ele deve apontar para o XML **2026**, não para o XML 2025.

Prefira sempre:

```bat
--base-xml-2026 "...xml"
```

## Manter ou trocar CPF/nome

Se não informar `--target-cpf` e `--target-name`, o comando mantém o CPF/nome do XML base 2026.

Se quiser gerar uma cópia para outro contribuinte ou teste:

```bat
irpf-importer migrar ^
  --base-xml-2026 "data\work\declaracoes\SEU_CPF\SEU_CPF-0000000000.xml" ^
  --target-dir "data\work\migracao_2026" ^
  --target-cpf "00000000000" ^
  --target-name "CONTRIBUINTE TESTE" ^
  --bens "data\input\bens\bens_2025_preparado_importacao.xlsx" ^
  --irpf-dir "%IRPF_DIR%"
```

Quando `--target-cpf` é informado, o comando também atualiza `cpfBeneficiario` nos itens.

## Bens e Direitos

A planilha de Bens usa o mesmo importador já validado:

- chave principal: `grupo + codigo + codigoNegociacao`;
- consolidação de duplicados da planilha;
- ignorar chaves ambíguas no XML;
- recálculo dos totais de Bens.

O XML 2026 normalmente já vem com o `valorExercicioAnterior` transportado do ano anterior. A planilha atualiza principalmente o `valorExercicioAtual`.

## Proventos

A importação de proventos ainda é mais simples que Bens:

- divide eventos em isentos/dividendos e JCP;
- `--proventos-mode replace` remove os itens dos quadros suportados e recria com base na planilha;
- campos não suportados devem ser conferidos manualmente no IRPF.

## Recibos

No fluxo `migrar`, o XML base é uma declaração 2026 que já existe e já é reconhecida pelo programa da Receita. Por isso, **recibos e metadados de transmissão são preservados por padrão**.

O comando padrão não altera:

- `numeroReciboDecAnterior`;
- `numReciboDecRetif`;
- `numReciboTransmitido`;
- indicadores de transmissão/retificadora quando existirem.

Se você estiver criando uma cópia de teste ou realmente quiser limpar esses campos, use explicitamente:

```bat
--limpar-recibos
```

Para sanitização de identidade/dados cadastrais, prefira o comando `clone`.

## Validação no programa da Receita

Depois de gerar a declaração na pasta de trabalho:

1. Feche o IRPF 2026.
2. Faça backup da pasta oficial em `aplicacao\dados\<CPF>`.
3. Copie a pasta gerada para a pasta oficial.
4. Abra o IRPF 2026.
5. Confira Bens, Rendimentos, Pendências e totais.
6. Se der erro, restaure o backup oficial.

## Correção de transmissão: atributo `tipo` em Bens

O programa IRPF 2026 usa o atributo técnico `tipo` dos itens de Bens com tamanho máximo de 1 caractere. Relatórios de corretoras podem trazer descrições como `ON`, `PN`, `PNA`, `PNB`, `UNIT`, `BDR`, `ETF` ou `Cotas`.

O importador agora normaliza automaticamente esses valores para `T` no atributo XML `tipo`. A descrição original continua preservada na `discriminacao`, por exemplo: ação PN, ação ON, BDR, ETF ou cotas de fundo.

Isso evita erro no envio como:

```text
Erro atribuindo conteudo ('PN') maior que o tamanho do campo IN_TIPO_BENEFIC. Tamanho esperado: 1
```

Depois de atualizar o projeto, gere novamente a declaração pela migração/importação e recalcule o `.conf`.
